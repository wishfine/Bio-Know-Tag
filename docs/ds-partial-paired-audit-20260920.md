# DS 10 万题阶段性成对实验审计

生成日期：2026-09-20  
分析对象：同一批题目上，`Hybrid Top25` 与 `Hybrid Top25 + 当前 458 体系内旧 knw_ids` 的 DS v9.1b 精判结果。

## 1. 结论先行

当前证据不支持把旧 `knw_ids` 无条件追加到所有题目的候选池。

原因不是旧 ID 完全没用，而是它带来的真实新增召回很少，同时会明显扰动 DS 对原 Top25 候选的判断：

- 当前可严格配对的题目有 27,673 道。
- Top25 产生 44,168 个 Label 赋值；Top25+旧 ID 产生 44,692 个，只净增加 524 个，增幅约 1.19%。
- 两组 Label 赋值的交集为 40,328，Top25 独有 3,840，Top25+旧 ID 独有 4,364；赋值级 Jaccard 为 83.10%。
- 稍早的 27,476 道共同成功快照中，有 5,391 道题的 Label 集合不同，题级差异率为 19.62%。
- 全部 10 万题的候选清单中，旧 ID 平均只让候选数从 25 增到 25.508；仅 33.27% 的题实际增加候选，最多增到 33 个。
- 风险抽样中的 1,626 个“Top25+旧 ID 独有”实例里，只有 117 个（7.20%）的目标 Label 排名超过 25、确属旧 ID 新补入；其余 1,509 个（92.80%）目标 Label 原本就在 Top25。后者仍需继续区分：该题是否另有其他旧 Label 被追加。如果一个也没有追加，则两次 prompt 完全相同，差异只能计为重复运行波动；如果追加了其他旧 Label，则属于候选集合扰动后的改判。

因此，目前可以确定的是“绝大多数旧 ID 独有赋值并非目标 Label 的新增召回”；但在补齐逐题候选集合对照前，还不能把它们全部归因于候选扰动，其中一部分可能只是相同 prompt 的重复运行波动。在高精度优先、允许少量漏标的目标下，建议：

1. 主流程以纯 Top25 为默认候选；
2. 旧 ID 不直接并入常规候选，而只作为召回失败时的救援信号；
3. 在最终冻结前，补做同一份纯 Top25 的重复运行，测量模型自身的基线不稳定率；
4. `生物学常识` 等语义兜底 Label 单独暂停，不因旧 ID 或检索命中而自动进入训练集。

## 4. 最关键的发现：先分清新增召回、候选扰动和重复运行波动

对风险样本中的 1,626 个“仅 Top25+旧 ID 选中”实例，按目标 Label 在增强候选中的位置拆分：

| 类型 | 数量 | 占比 | 含义 |
|---|---:|---:|---|
| 排名 26 以后、来源仅为 legacy | 117 | 7.20% | 旧 ID 真正补入了 Top25 之外的 Label |
| 排名 1–25 | 1,509 | 92.80% | 目标 Label 原已在 Top25；需再看该题是否追加了其他旧候选 |

代码核查表明：如果一道题的所有有效旧 `knw_ids` 都已经位于 Top25，增强脚本只会修改候选 sidecar 中的 `sources`、`method` 和 `retrieval_version`。这些字段均未写入精判 prompt；候选卡片还会按 `question_id + label_id` 做确定性重排。因此这类题的两次 prompt 逐字相同，输出差异必须归入模型或服务的重复运行波动。

只有当至少一个旧 Label 原本不在 Top25、被追加到候选集合时，prompt 才真正发生变化。此时又要区分：

1. 新追加的 Label 被选中：可能是真实补召回，也可能恢复历史错标；
2. 新追加的 Label 没被选中，但原 Top25 Label 的选择改变：属于候选集合扰动；
3. 没有追加任何 Label，结果却不同：属于同 prompt 重复运行波动。

例如题 `2141268958069469184` 明确比较真核细胞与原核细胞：

- `原核细胞和真核细胞` 在两组中本来都是第 4 候选，来源为 sparse+dense；
- 纯 Top25 没选它；
- 增强版本却选了它。

反向例子题 `2600839121303273472` 中，同一 Label 在纯 Top25 为第 24 候选并被选中，增强版本中又消失。两道题中该 Label 都有合理性，且目标 Label 均不是旧 ID 新补入。当前压缩包没有包含完整候选 sidecar，尚不能判断这些题是否追加了其他旧候选，因此只能归为“重复运行波动或候选竞争”，不能进一步二选一。

所以，`legacy_only_selected` 不能直接解释为“旧 ID 挽救了漏标”，`top25_only_selected` 也不能直接解释为“旧 ID 导致错标”。必须按逐题候选集合分成“同 prompt”“增加候选但新增项未选中”“新增候选被选中”三组后再分析。

这说明旧 ID 可以作为低成本召回提示，但适合做“救援候选”，不适合无条件改变每道题的常规候选上下文。

## 6. 旧 ID 也会恢复历史污染

题 `2555721438628167680` 讨论朊粒，旧 ID 将 `非细胞形态的生物--病毒` 作为第 26 个候选补入并被选中。朊粒是异常构象蛋白，不是病毒；这里仅共享“可传播/增殖/非典型病原体”背景，属于明确错标。

另一个高风险对象是 `生物学常识`：

- 历史正样本仅 49 道，DS 与当前释义匹配的只有 2 道，匹配率 4.08%，零分率 95.92%；
- 当前阶段仍有 32 道题被至少一组精判选中；
- 抽样涵盖植物激素、传染病、营养健康、垃圾分类、心理健康等彼此无统一知识边界的内容。

该 Label 不是普通的“边界略宽”，而是缺乏稳定可学习语义。建议 `TAXONOMY_HOLD`：不进入生成式训练标签，等待老师明确边界或确认移除。

## 7. 既有正负样本先验该怎么用

历史风险先验适合决定“抽多少、先看谁”，不适合直接决定生产结果对错。

典型例子是：

- `基因分离定律的实质与应用` 的历史校正边界错误率为 97.14%；
- `基因的自由组合定律的实质与计算` 为 96.55%。

但本次抽到的旧 ID 独有实例中，大多数题确实直接使用分离或自由组合规律，例如测交 1:1、两对独立遗传、9:7 变式、F2 比例计算等。按照项目已经确认的“合理共标可以接受”原则，这些不能因为相邻 Label 也能描述就一律判错。

因此，之前的硬负样本结果应继续作为风险排序特征，而不能被当作自动硬过滤规则。真正适合硬过滤的是对象、任务或生物层级明确冲突，例如“朊粒 ≠ 病毒”“固定化脲酶 ≠ 分离尿素分解菌”。

## 9. 当前建议的主流程

### 默认路线

`Hybrid Top25 → DS v9.1b 精判 → 现有硬过滤 → 训练过滤`

纯 Top25 更符合当前“宁可漏标、一定控制错标”的目标，也避免把历史体系的错误作为隐式先验重新注入。

### 旧 ID 的保留方式

旧 ID 不废弃，但只用于以下场景：

1. 纯 Top25 输出为空；
2. `need_expand_recall=true`；
3. 旧 ID 属于当前 458，且不在 Top25；
4. 旧 Label 不属于兜底、综合、图谱冲突或人工暂停集合；
5. 以单个补充候选做独立确认，确认失败则保持空标签。

如果暂时不想增加第二次模型调用，也可以直接不做旧 ID 救援；按当前目标，少量漏标比系统性错标更可接受。

### 冻结前还缺的一个对照

第一步应直接利用现有两组 10 万候选 sidecar，按题划分：

- `same_candidate_set`：所有旧 ID 已在 Top25，两个 prompt 完全相同；
- `candidate_set_expanded`：至少有一个旧 ID 被追加；
- `added_legacy_selected`：新增旧 Label 最终被选中。

其中 `same_candidate_set` 本身就是现成的重复运行稳定性对照，不需要额外调用 DS。若该组题量不足，再对同一批 2,000–5,000 道题重复运行一次“纯 Top25 + 同 prompt + 同参数”，计算：

- 题级 Label 集合完全一致率；
- 赋值级 Jaccard；
- 空/非空翻转率；
- 每个 Label 的重复运行不一致率。

只有先量出模型自身的重复运行波动，才能把 Top25 与 Top25+旧 ID 的差异中有多少真正归因于候选增强。若纯 Top25 自身差异也接近当前水平，就应先处理服务或解码稳定性，而不是继续调召回。
