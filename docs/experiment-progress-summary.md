# 高中生物知识点打标项目实验进展总结

更新日期：2026-09-15

## 1. 项目目标与当前结论

本项目目标是使用 DeepSeek-V4-Flash（以下简称 DS）为大规模高中生物题生成知识点 Label，再用这些数据训练生成式知识点打标模型。

当前冻结的主链路为：

```text
不可变题库清洗基线
→ 独立题/小题打标单元
→ BM25 + Dense 混合召回 Top25
→ DS 联合精判
→ 空标、扩召、上下文不足和异常题过滤
→ 精确重复题结果回填
→ 父题 Label = 小题 Label 并集 + 父题材料额外考点
→ 独立 Label sidecar
```

阶段性结论：

1. 458 个 Label 的老师释义整体质量较高，生产打标应以老师释义为权威边界，不用 DS 自生成释义替换。
2. 旧 `knw_ids` 不参与生产打标，只作原始数据溯源保留。
3. 混合 Top25 在 298 道可判定样本上至少召回一个真 Label 的题有 293 道，保守 Recall@25 为 **98.32%**，证明无需让 DS 遍历 458 个 Label。
4. DS 精判的主要风险是“相邻但考查维度不同的 Label 互相替代”与“过度保守导致可用题被置空”。
5. v7 代码已完成，但尚未在服务器重跑 300 题。在 v7 实测通过前，不应启动 185 万打标单元的全量 DS 运行。

## 2. 统一数据口径

### 2.1 Label 体系

- Label 总数：458。
- 权威定义：`definition`、`core_concepts`、`common_assessments`、`distinctions`。
- 路径对外统一使用 `@` 分隔。
- Stage 1 的 DS 释义只用于评估名称可理解性，不进入生产 Label Card。

### 2.2 题库与打标粒度

| 对象 | 数量 | 处理方式 |
|---|---:|---|
| 独立题 | 1,033,000 | 根据自身题干、选项、答案和解析打标 |
| 正常组合题小题 | 823,136 | 带父题公共材料，每个小题独立打标 |
| 缺父题小题 | 1,455 | 视为独立打标单元，只打自身 Label |
| 第一层打标单元 | **1,857,591** | 需要召回与精判 |
| 真实组合题父题 | 219,741 | 小题 Label 并集加父题额外考点 |
| 虚拟父题容器 | 388 | 不产生最终父题 Label |

最终应产生 1,857,591 + 219,741 = **2,077,332** 条真实题目结果，与原始真实题目记录数一致。

## 4. 实验详细记录

### 实验 1：Label Excel 导出与 taxonomy 检查

**目的：** 将老师 Excel 转换为机器可读 Label Card，排除空字段、重复 ID/名称和路径冲突。

**结果：** 成功导出 458 个 Label；空字段、重复 ID、重复名称和处理错误均为 0。名称风险分层包括“综合”52 个、“实验”33 个、“应用”20 个、“其他”5 个（非互斥）。发现 `蛋白质病毒的增殖` 名称与释义明显不一致。

**结论与改进：** 结构可直接进入实验，但结构通过不代表语义正确。不修改老师原 Excel，只在 JSONL 和复核台账中记录风险；`蛋白质病毒的增殖` 留给老师确认。

### 实验 2：原始题库清洗与大小题聚合

**目的：** 清理 4.8 GB JSONL 的嵌套 `question_info`、HTML、选项、答案和解析，并把小题按 `parent_id` 聚合。

**结果：** 100 题 smoke 初次因脚本直接执行时找不到 `bio_know_tag` 失败，修正导入后通过。100,000 题验证实现 `processed=100000`、`error=0`。全量实现 `input=processed=2,077,332`、`error=0`、`skipped=0`；小题 824,591，聚合后顶层记录 1,253,129，文件约 2.8 GB。

**结论与改进：** 数量闭环且抽查结构正常。不再重写 2.8 GB 文件，将其固定为不可变基线；后续答案规范化、候选和 Label 都用派生文件/sidecar。

### 实验 3：388 个缺父题聚合组审计

**目的：** 解释 `parent_count + child_count - processed = 388`，判断这些数据能否打标。

**结果：** 1,455 个小题引用 388 个缺失父题 ID。388 个虚拟容器均能在聚合输出找到，但父题题干全为空；1,455 个小题自身题干全部非空，抽查显示多数可依据自身内容判断知识点。

**结论与处理：** 这是原始数据缺父题，不是脚本丢数据。小题保留并设置 `parent_context_missing=true`，只打自身 Label；388 个容器不生成父题 Label。方案已固定，无需再改。

### 实验 4：Stage 1——DS 只看 Label 名生成释义

**目的：** 不给老师释义和题目，只给 Label 名，测试名称自身的信息量。

**结果：** 458 个 Label 全部生成成功，每条产生 `core_meaning`、`included_content`、`excluded_content`。大多数明确名称能被 DS 正确理解；“综合”“其他”、教材活动和名称-释义冲突项不能仅靠名称稳定判标。

**结论与不改进理由：** Stage 1 已完成诊断目的，不重跑。DS 释义不替换老师释义；后续生产以老师边界为准。

### 实验 5：Stage 2——DS Judge 对齐实验

**目的：** 对比老师释义与 Stage 1 释义，区分名称可自解释、必须给释义和 taxonomy 问题。

**过程修正：** 最初 Judge 容易把“DS 写得更详细”当成“名称不足”。Prompt 后续改为只评估“名称能否稳定决定题目是否属于该 Label”，不受文字详略影响。

**结果：** L1/L2/L3 = 410/26/22；对齐分 1/2/3/4/5 = 2/4/11/409/32。L3 规则为分数 ≤3，或 Judge 认为 DS 释义更准确/两者都有问题/无法判断，或名称存在体系问题；L2 是剩余“需要原释义”项；其余为 L1。

**结论与不改进理由：** 大部分 Label 主题清晰，但真实打标仍需老师边界。不增加 embedding 相似度，因为它只能衡量主题接近，不能替代“实验 vs 原理”等判标边界审核。

### 实验 6：GPT 二次复核、逐 Label 策略与教师复核表

**目的：** 避免 DS 同时担任释义生成者和唯一裁判者，并将 458 Label 转成可执行策略。

**结果：** 第二遍复核调整 23 个 Label。最终状态：`confirmed=394`、`confirmed_with_caution=28`、`adjusted=23`、`routed_separately=12`、`taxonomy_hold=1`。最终策略：`compact_definition=224`、`name_plus_boundary=188`、`strict_definition=33`、`separate_dimension=12`、`taxonomy_hold=1`。两个有丝分裂观察 Label 已由业务口径确定为“知识点本身 vs 教材实践活动”，不再要求老师复核。另生成 10 个高优先级教师复核项：9 个“两者都有问题”项加 `蛋白质病毒的增殖`。

**结论与改进：** 没有证据表明 DS 释义普遍优于老师释义。DS 理解不同时，直接发老师原释义，不为适应 DS 反向改写。仅 10 个高风险项留给老师，其他项不再追求释义“完美化”。

### 实验 7：旧 `knw_ids` 覆盖和 R0/R1/R2 dry-run

**目的：** 评估旧 ID 能否直接映射新 458 Label，并减少 DS 调用。

**结果：** 100,000 题中 89,843 题至少命中一个新 Label，89,689 题的全部 ID 都属于新 458；124,531 个 ID 赋值中命中 114,112。未匹配 ID 有 11 种，其中 `2099278345084715008` 出现 9,402 次，像旧体系兜底 ID。全量 dry-run 曾得到 `R0=395,961`、`R1=1,307,077`、`R2=154,553`。

**结论与弃用理由：** 旧 ID 有信息量，但组合题中往往像父题 Label 并集，还有未映射 ID 和重复题冲突。最终取消旧 ID 消融：它们不进入召回、Prompt、路由、Pilot 评价或训练标签。

### 实验 8：全量打标单元、去重与父题计划

**目的：** 在不改写 2.8 GB 基线的前提下，构建真正进入召回/DS 的单元，规范化 `answer_text`，并估计去重收益。

**结果：** 1,857,591 个打标单元；219,741 个真父题聚合计划；35,484 个精确重复组、78,626 个成员，理论减少 43,142 次 DS 调用，去重后约需 1,814,449 个独立判断。空题干8、空答案文本5,476、空解析21,148、图片上下文风险标记880,178。派生目录约 4.2 GB。

**结论与改进：** 数据契约固定为“独立题+小题先判，父题后聚合”。早期“父题不打标”已修正为“父题=小题并集+父题额外考点”。全量物化前还需增加确定性结构过滤：空题干、非生物题、只有公共材料但无设问且答案解析为空的记录不进训练。

### 实验 9：无旧标签依赖的 2,500 题 Pilot

**目的：** 构建足够小但覆盖主要数据形态的实验集，用于召回和精判选型。

**结果：** 独立题 1,132、正常小题 1,192、缺父题小题 176；完整保留 200 个父题组，抽取 100 个精确重复组、图片风险样本300、空题干8、空答案样本100、空解析样本100。`legacy_fields_used=false`。

**结论与不改进理由：** 该 Pilot 适合工程选型和失败模式发现，不足以分别估计 458 Label 的准确率。当前不扩大工程 Pilot，先固定召回和 Prompt，避免版本同时变化无法归因。

### 实验 10：字符 n-gram BM25 稀疏召回

**目的：** 使用无模型依赖的本地方法，从 458 Label 中召回教材术语、实验操作和专有概念。

**结果：** 2,500/2,500 成功，`error=0`，每题 Top20；约 29 秒完成，输出约 12 MB。人工查看显示，BM25 在教材固定术语、遗传计算、生态工程和细胞自噬等题上较强。

**结论与改进：** BM25 适合做主召回，但对语义改写和隐含机制不足。不为海量题目编写无法穷举的关键词规则；引入 Dense 补语义，仅保留少量可泛化 taxonomy 扩展作为备选。

### 实验 11：DS 全 458 Label 粗召回

**目的：** 测试 DS 一次阅读全部 Label 名称/路径并给出 Top20 的召回基线。

**结果：** 10 题 smoke 中存在重复 Label 和超过 Top20 的输出，导致 `candidate_label_ids exceeds top_k`。后续代码使用 `B001`–`B458` 短代码，增加去重和截断，修复了格式层问题。

**结论与终止理由：** 不继续跑 2,500 题 DS 粗召回。它仍需长上下文和 DS 调用，不符合效率目标；DS 调用预算留给 Top25 精判。代码保留为历史基线。

### 实验 12：BGE Dense 召回与 BM25 分歧

**目的：** 检验稠密语义召回能否补充 BM25 的隐含语义和改写表达。

**方法与结果：** 使用 A800 和 `BAAI/bge-small-zh-v1.5`（约24M参数），对 458 Label 直接做精确余弦排名，不需要向量库。2,500/2,500 成功，`error=0`，约 3 秒完成。BM25/Dense Top1 一致 1,049/2,500，一致率 41.96%；平均 Top20 交集 9.2528，平均 Jaccard 0.316809；导出 200 个最大分歧样本。

**结论与改进：** 两路差异显著，Dense 有互补价值，但重合率不是准确率。人工查看显示 BM25 教材术语更稳，因此不采用 Dense 单路或等权融合，而用 BM25 主导的配额融合。

### 实验 13：BM25 18 + Dense 7 混合 Top25

**目的：** 保留 BM25 精确术语优势，同时用 Dense 增加新语义候选，将 DS 每题阅读量从 458 个 Label 降到 25。

**方法与结果：** 先保留 BM25 Top18，再加入 Dense 中前 7 个新 Label，不足 25 时才用 RRF 补齐。上游两路均重跑 Top30，避免两个 Top20 并集不足 25。最终 2,500 题每题均有 25 个候选。

**结论：** 冻结为当前 Pilot 召回版本 `hybrid-v1-s18-d7-k25`。它是待验证的工程参数，不声称是永久最优比例。

### 实验 14：300 题 Recall@25 人工审计

**目的：** 验证每题 Top25 中是否至少有一个真正考查的 Label。不要求覆盖全部真 Label，也不评价 DS 最终选择。

**结果：** 200 题 representative 中 196 hit、3 miss、1 invalid；100 题 stress 中 97 hit、2 miss、1 invalid。可判定 298 题中 293 hit，Recall@25 = **98.32%**。5 miss 包括 2 个 taxonomy 缺项（胡萝卜素提取、凝胶过滤）、1 个 taxonomy 边界不足（生物入侵）和 2 个算法漏召（数据图像类、施肥烧苗的渗透作用）。2 invalid 为无实际设问和非生物文案。

**Top20/25 结论：** v4 中 17 题使用第21–25名，共 19 个尾部 Label；人工审计为 14 个明确有用、3 个错选、2 个边界项。因此尾部候选有增益，当前保留 Top25，不降回 Top20。

**改进方案：** 不为 5 道 miss 编写大量题目关键词规则。taxonomy 缺项留给老师；算法漏召可以用 taxonomy 兄弟软扩展。若 DS 能稳定对缺候选题输出空并过滤，少量 miss 可接受，不为追求 100% 显著提高全量成本。

### 实验 15：Top30 与 Cross-Encoder Reranker

**目的：** 比较“BM25 Top20 + Dense 独有 Top10”和 `BAAI/bge-reranker-base` 对两路并集重排的 Top30，尝试解决召回 miss。

**结果：** 已完成 Dense 长文本头尾截断、Cross-Encoder 重排代码、模型下载和运行命令，但尚无完整同口径对比报告或人工审计。

**结论与暂停理由：** 这是“已实现、未验证”，不能宣称 reranker 有增益。现有 Top25 Any-Hit 已达 98.32%，当前更明显问题在精判；因此固定召回，先验证 v7。若 v7 后扩召仍多，再恢复 reranker 实验。

### 实验 16：DS 连通性、延迟、thinking、流式和重试

**目的：** 判断精判慢是 Prompt 太长、thinking、非流式还是服务负载造成，并完善断点续跑。

**结果：** 请求使用 `stream=false`，`reasoning`/`reasoning_content` 为空，未开 thinking。9102 最小请求仅 13 输入 Token、6 输出 Token，仍耗时 77.98 秒；9103 同类请求耗时 52.26 秒。v6 的 300 题中，51 题成功前发生重试，成功记录累计保留 195 次 `ConnectionResetError`；多次断点续跑后最终 300/300 成功。

**结论与改进：** 主因是服务排队/负载或连接，不是 Token 数单独造成。已增加带抖动退避、可配置重试、请求诊断、全局 `request_interval`、每题立即落盘和输入哈希恢复。不依赖流式解决：流式只改善首 Token 可见时间，不解决排队/重置，批处理更需要 JSON 完整性和可恢复性。

### 实验 17：DS 候选精判 v4（300 题）

**目的：** 每题发送 25 个混合候选及老师释义，验证 DS 联合裁决，并区分召回缺口与上下文缺口。

**结果：** 续跑后 300/300 成功，`error=0`。`none_of_candidates=11`、`need_expand_recall=14`、`context_insufficient=18`。平均输入 10,238 Token，输出 335 Token，总 Token 约 10,573；平均延迟 104.3 秒。17 题使用第21–25名，共 19 个尾部 Label。evidence 字符校验有 73 题、128 个项未逐字匹配；后续确认主要是空格、LaTeX、标点和轻度改写，不等于错标。

**结论与改进：** 候选联合精判可行，但 v4 输出冗长，证据/理由增加延迟，并存在背景过打和状态不稳定。保留 Top25 和老师释义，删减输出字段，只判当前小题，允许空结果并过滤。初审曾记录 13 题精判问题、7 题召回缺口漏报和 1 题数据异常；后续在“合理多标算对、允许漏标/空标”口径下，部分不再属于阻塞错误。

### 实验 18：紧凑输出 v5

**目的：** 删除 `rejected_close_codes`、逐 Label `necessity`和全局 `reason` 等非必要输出，降低解码时间和 JSON 截断风险。

**结果与不改进理由：** v5 完成了代码/协议设计，但没有独立完成同一 300 题对比，因此不报告准确率改善。紧凑化思路已被 v6/v7 继承，不再单独补跑 v5。

### 实验 19：精度优先 v6（300 题）

**目的：** 面向训练数据，强调错标代价高于漏标，允许少选和置空。

**结果：** 300/300 成功，`error=0`。共选 595 个 Label，平均 1.98/题；`none_of_candidates=21`、`need_expand_recall=14`、`context_insufficient=34`。251 题可进训练，49 题被过滤。平均输入 8,506.7 Token，比 v4 下降 16.9%；平均输出 85.95 Token，下降 74.3%。9 题使用第21–25名，共 10 个尾部 Label。

**结论：** v6 修复了多个 v4 错标，例如删除 DNA 复制小题中的“转录”、噬菌体展示题中的“动物细胞融合”和新冠疫苗题中的“热点聚焦”。但“更具体 Label 优先”造成跨维度替代：施肥烧苗被打成质壁分离实验，“细胞是基本单位”额外打成细胞学说发展史，水跨膜额外打成水的存在形式。

**改进：** 不回退 v4。保留紧凑输出和空标过滤，但将“最小集合/更具体优先”改为“合理多标可保留，边界与考查维度优先”。

### 实验 20：v4/v6 300 题逐题对照

**目的：** 逐题对照题干、父题材料、选项、答案、解析、v4/v6 Label 和过滤状态，确认改动是提升精度还是只减少样本。

**口径：** 合理多标不算错；允许漏标/空标；空结果被过滤不算污染；只有错 Label 被保留且进训练才算精度改差。

**结果：** v6改好27题；v6精度改差7题；v6覆盖下降7题；路由状态改差2题；两版均需处理8题；等价可接受249题。

**结论与改进：** v6 总体方向正确，不应整体回退 v4。需修复的是跨维度替代和过度保守，不是增加更多理由字段或再做一层全量 DS Judge。完整 300 行明细见 `docs/pilot-v4-v6-300-question-review.md`。

### 实验 21：平衡精度与覆盖的 v7（待运行）

**目的：** 同时修复 v6 的7道精度回归和7道覆盖下降，保留紧凑输出和空标过滤。

**已完成的改动：** 合理多标可保留；增加原理/实验/应用/结论/发展史维度硬边界；`distinctions` 作为硬排除；答案/解析能确定 Label 时不因缺图过度过滤；候选只有跨维度近似项时返回空并扩召；删除 evidence/理由，只输出 Label 短代码和两个缺口布尔值。

```json
{
  "selected": ["C01", "C05"],
  "need_expand_recall": false,
  "context_insufficient": false
}
```

**当前验证：** 本地 91 项测试通过。同一 300 题的 v7 Prompt 平均比 v6 增加 203 字符（约1.3%）；由于删除 evidence，输出预期更短，但尚无 DS usage 结果。

**当前结论与下一步：** v7 是“代码已就绪”，不是“实验已通过”。必须用原 300 题、原 `hybrid-v1-s18-d7-k25` 候选重跑，不同时改召回。验收时优先看7道精度改差、7道覆盖下降、2道路由回归和8道两版均有问题的题。

## 5. 已否定、暂停或保留备用的方案

| 方案 | 决定 | 理由 |
|---|---|---|
| 每题对 458 Label 逐一二分类 | 否定 | 约8.5亿次级判断，调用量不可接受 |
| 每题一次发 458 个完整释义 | 否定 | 输入过长，无关 Label 稀释边界判断 |
| DS 全 Label 粗召回 | 终止 | DS 更适合 Top25 精判，不适合大规模第一层召回 |
| 直接继承旧 `knw_ids` | 否定 | 旧体系、父题并集和冲突风险会污染新标签 |
| 仅 BM25 | 不单独用 | 精确术语强，语义改写弱 |
| 仅 Dense | 不单独用 | 可补语义，教材术语不如 BM25 稳定 |
| Top20 | 暂不采用 | 第21–25名确实补回多个合理 Label |
| Top30/reranker | 保留备用 | Top25 Any-Hit 已高，先固定召回并修精判 |
| 为所有 miss 编写题目关键词规则 | 否定 | 题目表达无法穷举，易形成脆弱规则库 |
| 要求 DS 必须非空 | 否定 | 空标可过滤，强制非空反而增加错标 |
| 对所有结果再做一次 DS Judge | 暂不采用 | 成本加倍，应先修复一次精判 Prompt |
| 保留 evidence 作为模型输出 | v7删除 | 增加解码并促使表面词反向合理化；字符校验不能证明语义正确 |

## 6. 当前风险与待办

1. **v7 尚未实跑。** 这是当前阻止全量打标的核心问题；本地测试不能代替 DS 语义实测。
2. **taxonomy 缺项。** 已知胡萝卜素提取、凝胶过滤两个明确缺项，以及生物入侵边界不足。老师决定前允许空标并过滤。
3. **输入异常过滤尚待物化。** 空题干、非生物文案、只有公共材料无设问的记录应用本地确定性规则过滤，不浪费 DS。
4. **DS 服务稳定性。** 极短请求仍有50–78秒延迟和连接重置，全量前必须在稳定服务上测持续吞吐。
5. **尚无完整金标。** 300 题已有 Any-Hit Recall 审计和 v4/v6 对照，但并非每题所有真 Label 的严格金标；不应宣称精确 Precision/Recall/F1。
