# 旧 `knw_ids` 对 DS 精判的扰动分析

日期：2026-09-20  
对照实验：纯 `Hybrid Top25` vs `Hybrid Top25 + 当前 458 体系内旧 knw_ids`，二者均使用 DS v9.1b 精判。

## 1. 扰动必须拆成三类

不能把所有两组差异都归因于“旧 ID 有效”或“旧 ID 有害”。对每道题应先判断候选集合是否真的变化。

### A. `same_candidate_set`：候选集合未变化

该题所有有效旧 `knw_ids` 都已在 Top25。

增强脚本虽然会：

- 在候选 sidecar 的 `sources` 中加入 `legacy`；
- 修改 `method`；
- 修改 `retrieval_version`；

但精判 prompt 不包含这些字段。精判只发送候选的：

- label_name；
- label_path；
- definition；
- core_concepts；
- distinctions。

候选还会按 `question_id + label_id` 做确定性哈希排序。因此，当候选 ID 集合相同时，两次 prompt 逐字相同，code_map 也相同。

这组题若输出不同，只能计为 DS/服务的重复运行波动，不能归因于旧 ID。

### B. `candidate_set_expanded_but_added_not_selected`：增加候选，但新增项未被选中

至少一个旧 Label 不在 Top25，被追加到第 26 位以后，但最终新增 Label 没有被选中；与此同时，原 Top25 Label 的选择发生变化。

这是纯粹的候选集合扰动：旧 ID 没有直接贡献最终 Label，却通过改变上下文、代码编号和候选竞争关系改变了模型判断。

### C. `added_legacy_selected`：新增旧 Label 被选中

旧 ID 真正补入 Top25 之外的候选，并最终被 DS 选中。

该组才是旧 ID 的实际召回贡献，但仍需逐题区分：

- 有效补召回；
- 合理共标；
- 历史错标恢复；
- 父题并集或旧体系语义漂移。

## 2. 当前观察到的量级

当前严格配对成功题为 27,673 道。

| 指标 | 数值 |
|---|---:|
| 两组共同 Label 赋值 | 40,328 |
| 仅 Top25+旧 ID 赋值 | 4,364 |
| 仅纯 Top25 赋值 | 3,840 |
| Label 赋值并集 | 48,532 |
| 赋值级 Jaccard | 83.10% |
| 纯 Top25 总赋值 | 44,168 |
| Top25+旧 ID 总赋值 | 44,692 |
| 旧 ID 净增加 | 524（相对 Top25 为 +1.19%） |

稍早的 27,476 道共同成功快照中，有 5,391 道题的最终 Label 集合不同，题级差异率为 19.62%。

与此同时，全 10 万题候选文件中：

| 候选数 | 题数 |
|---:|---:|
| 25 | 66,728 |
| 26 | 20,397 |
| 27 | 8,975 |
| 28 | 3,248 |
| 29 | 607 |
| 30–33 | 45 |

旧 ID 平均只增加 0.508 个候选；66.73% 的题没有增加任何候选，33.27% 的题候选集合扩大。

这意味着：一个很小的候选集合变化对应了相当大的输出变化。净增加只有 524 个 Label，但两边独有赋值合计达到 8,204 个。旧 ID 的主要可见效应不是单向补标签，而是让已有 Label 在“选中/不选中”之间双向翻转。

## 3. 风险抽样揭示的结构

风险复核样本中共有 1,626 个 `legacy_only_selected` Label 实例：

| 目标 Label 情况 | 数量 | 占比 |
|---|---:|---:|
| 目标 Label 位于第 26 位以后，仅由 legacy 新增 | 117 | 7.20% |
| 目标 Label 本来就在 Top25 | 1,509 | 92.80% |

因此，至少在该风险抽样中，绝大多数“增强后才选中”并不是目标 Label 被旧 ID 新召回，而是目标 Label 原已存在、第二次运行发生改判。

但 1,509 条还不能直接全部叫作“候选扰动”，因为当前小压缩包没有完整候选 sidecar，无法继续判断该题是否追加了其他旧 Label：

- 若没有追加其他 Label：属于完全相同 prompt 的重复运行波动；
- 若追加了其他 Label：属于候选集合扰动。

## 4. 为什么候选只增加一点，结果却变化很多

### 4.1 相同 prompt 也可能不完全确定

客户端请求设置了 `temperature=0`，但没有设置服务端 `seed`。大模型服务仍可能受以下因素影响：

- GPU 浮点归约顺序；
- 动态 batching；
- MoE 路由或并行执行；
- 不同服务副本或不同时间的运行状态；
- 接近决策边界时极小 logit 差异被放大。

因此，完全相同 prompt 仍可能出现 Label 集合差异。`same_candidate_set` 正好可以直接测量这种基线波动。

### 4.2 新候选会改变所有候选的 code 和相对位置

精判前会对所有候选按确定性哈希重新排序，再依次编码为 C01、C02……。新增一个 Label 后：

- 新 Label 被插入哈希序列；
- 它后面的若干原候选 code 会改变；
- 候选卡片总数和 prompt 长度改变；
- 模型需要在更大的集合中执行最小充分子集选择。

即使新增 Label 最后没被选择，也可能改变模型对其他 Label 的注意力和相互比较结果。

### 4.3 Label 之间存在语义重叠和层级竞争

容易发生扰动的典型组合包括：

- 分离定律、自由组合定律、伴性遗传、基因定位；
- 细胞膜结构、细胞膜功能、物质运输；
- 酶的特性、影响酶活性的因素、酶相关探究实验；
- 微生物培养、无菌技术、培养基配制；
- 通用规律与具体实例；
- 原子 Label 与综合/常识 Label。

新增一个邻近 Label 后，模型可能：

- 用更宽 Label 替换原子 Label；
- 用更具体 Label 替换通用 Label；
- 因高精度提示而只保留其中一个；
- 把两个都保留；
- 因边界冲突而两个都不选。

所以扰动是双向的，并不天然增加召回。

### 4.4 旧 ID 是带噪声的历史先验

旧 `knw_ids` 的来源并非当前小题的验证真值，可能包含：

- 组合题父题级 Label 并集被复制到小题；
- 同题多次录入但历史标签不同；
- 旧图谱与当前 458 图谱的语义漂移；
- 宽 Label、综合 Label 或兜底 Label；
- 题目只出现相关名词，却没有直接考查；
- 旧人工打标尺度与当前“高精度、允许漏标”尺度不同。

增强脚本不会告诉 DS “这是低置信历史候选”。新增 Label 在 prompt 中与 BM25/Dense 候选完全同权，因此历史噪声一旦进入候选池，就可能被模型当作正常候选选中。

## 5. 不同风险层的扰动程度

| 风险档 | Label 数 | 赋值级 Jaccard | 旧 ID 独有 | Top25 独有 | 净变化 |
|---|---:|---:|---:|---:|---:|
| HIGH | 253 | 80.08% | 2,135 | 1,902 | +233 |
| MEDIUM | 98 | 82.88% | 1,238 | 1,096 | +142 |
| STABLE | 107 | 87.48% | 991 | 842 | +149 |

高风险 Label 的一致性最低，说明释义边界、历史标签噪声和相邻 Label 重叠会放大候选扰动。但 STABLE 组仍有约 12.5% 的赋值并集不一致，因此服务/模型基线波动同样不可忽略。

## 6. 代表性 Label

### 6.1 原核细胞和真核细胞：典型双向翻转

- 净增加 66，是所有 Label 中最高；
- 旧 ID 独有 83，Top25 独有 17；
- 历史正样本匹配率 86.8%，历史边界风险低。

Luna 抽样中：

- 题 `2141268958069469184`：目标 Label 本来就是第 4 候选，纯 Top25 未选，增强版本选中；Luna 判合理共标。
- 题 `2600839121303273472`：目标 Label 是纯 Top25 第 24 候选并被选中，增强版本反而未选；Luna同样判合理共标。

这两条都不是目标 Label 的召回问题，而是相同合理 Label 在两次运行中双向翻转。是否由其他新增候选触发，需要完整候选 sidecar 才能确定；若两题都没有新增其他候选，就是纯重复运行波动。

### 6.2 基因分离定律：真实补召回与历史污染同时存在

该 Label 抽到 8 条 `legacy_only_selected`：

- 2 条目标 Label 确实由旧 ID 新增到第 26 位；
- 6 条目标 Label 本来就在 Top25。

两条真实新增恰好展示了旧 ID 的两面性：

| 题目 | 旧 ID 新补结果 | Luna | 复核 |
|---|---|---|---|
| `2611387220626259969`，由 11:1 反推 DD:Dd | 第 26 位补入分离定律 | DIRECT_MATCH | 有效补召回 |
| `2634176871933767680`，隐性突变互补检验 | 第 26 位补入分离定律 | WRONG_LABEL | 历史错标恢复 |

也就是说，同一个 Label、同一种旧 ID 补入机制，可以同时产生真正收益和明确错误，不能按 Label 或旧来源整体继承。

其余目标本来就在 Top25 的差异中：

- 有直接匹配，如孟德尔测交、面包霉孢子分离；
- 有合理共标，如伴性遗传比例推算；
- 有明确错标，如 SSR 基因定位。

这说明第二阶段 DS 自身的边界稳定性也是核心变量。

### 6.3 生物学常识：宽 Label 的选择容易翻转，但不一定是错

该 Label 抽到：

- 4 条旧 ID 独有；
- 8 条 Top25 独有；
- 8 条两组都选。

20 条经 Luna 按当前释义均判为合理。因为项目已确认宽 Label 只要符合释义即可保留，所以这里的双向变化主要反映模型对“是否还要补一个宽 Label”的不稳定，而不是错误率。

这类 Label 会显著降低两组集合一致率，但未必降低语义正确率。评估时应把“集合一致性”和“合理性”分开。

## 7. Luna 45 条盲审对两组的提示

| 来源状态 | 条数 | Luna 判合理 | Luna 判错 |
|---|---:|---:|---:|
| 两组都选 | 20 | 20 | 0 |
| 仅 Top25+旧 ID | 13 | 10 | 3 |
| 仅纯 Top25 | 12 | 11 | 1 |

按项目最新的“合理共标可接受”口径复核后：

- 旧 ID 独有中的伴性遗传表型推算应从错标改为合理共标，因此约为 11 条合理、2 条明确错标；
- Top25 独有中的单体/三体定位属于严格口径下的错标、宽松共标口径下的边界合理题。

该样本是风险分层抽样，不能用来估计全量精度。但方向上显示：

1. 两组共同选择的 Label 最稳定；
2. 旧 ID 独有结果中既有有效补召回，也有历史噪声；
3. 纯 Top25 独有结果多数也合理，说明增加旧候选会压掉一部分原本合理的 Label；
4. 只看标签数量净增加会掩盖双向翻转。

## 8. 当前不能从小压缩包回答的问题

当前压缩包没有包含两份完整候选 sidecar，因此尚不能精确统计：

- 27,673 道共同题中有多少属于完全相同 prompt；
- 相同 prompt 的题级集合一致率；
- 候选真正扩大后但新增项未选中的扰动率；
- 新增旧 Label 被选中的总题数与总 Label 数；
- 每增加 1/2/3 个候选时，输出翻转率如何变化；
- 某个原 Label 消失是否与某个新增邻近 Label 竞争有关。

这几项是判断旧 ID 是否值得进入主流程的关键，必须在服务器端用：

- `hybrid/candidates.jsonl`；
- `legacy-augmented/candidates.jsonl`；
- 两组最终 predictions/evidence；

按 `question_id` 做逐题连接后计算。

## 8.1 小压缩包中可以精确识别的 C 类

以“目标 Label 的 candidate_rank > 25 且 sources 仅为 legacy”为严格条件，小包中可以确认：

| 指标 | 数值 |
|---|---:|
| `added_legacy_selected` Label 实例 | 117 |
| 涉及题目 | 116 |
| 第 26 位 | 100 |
| 第 27 位 | 15 |
| 第 28 位 | 1 |
| 第 29 位 | 1 |
| 独立题 | 117 |
| 缺父题 | 0 |
| DS 标记 context_insufficient | 3 |
| DS 标记 need_expand_recall | 4 |
| 重复题结果不一致 | 3 |

117 条中有 48 条带 `image_context_missing` 标记，但抽样 sidecar 均未标为必须看图才能复核，且只有 3 条被 DS 判上下文不足。因此，题目缺失或父题污染不是这批 C 类的主要解释。

其历史边界风险分布为：

| 历史边界状态 | 数量 |
|---|---:|
| D_BROAD_BOUNDARY_REVIEW | 46 |
| B_MINOR_BOUNDARY_REVIEW | 25 |
| A_STABLE_CANDIDATE | 16 |
| C_NARROW_OR_LEGACY_NOISE_REVIEW | 15 |
| E_BOUNDARY_CONFLICT_REVIEW | 7 |
| U_INSUFFICIENT_VALID_NEGATIVES | 7 |
| U_LONG_TAIL_REVIEW | 1 |

只有 16/117 来自历史边界稳定组。其余多数本来就存在宽边界、相邻知识重叠、旧标签噪声或证据不足风险。这说明 C 类问题主要来自“旧 ID 质量 × Label 重叠 × DS 边界判断”的组合，而不是题目文本普遍残缺。

高频新增 Label 包括：

- 伴性遗传的分类与应用：6；
- 扩散作用与渗透作用及相应实验：5；
- 细胞膜的功能：4；
- ATP 在生命活动中的作用和意义：4；
- 内环境的概念及组成：4；
- 衰老细胞的主要特征、免疫失调、信息传递的农业应用、目的基因检测与鉴定：各 3。

这些大多是通用机制、应用或容易与相邻 Label 共存的知识，天然更容易出现“合理共标”和“历史宽打”混杂。

## 8.2 当前 Luna 5,776 条结果只能作弱证据

在分析期间，`runtime/luna-three-label-audit/item_reviews.jsonl` 从 45 条校准记录扩展为 5,776 条全量记录。对 117 条 C 类的输出为：

| Luna 决策 | 数量 |
|---|---:|
| DIRECT_MATCH | 13 |
| REASONABLE_CO_LABEL | 44 |
| WRONG_LABEL | 60 |

若直接采用该结果，则 C 类约 48.7% 可接受、51.3% 错标。但目前不能把这个比例当作可靠准确率，因为全量 Luna 文件存在明显质量风险：

- 5,776 条共用同一个 `reviewed_at`；
- reason 只有 4 种模板文本；
- 1,007 条 WRONG_LABEL 中的解释高度统一；
- 早先 45 条校准中已发现 evidence 串题和合理共标判严；
- 同一两道分离定律题在校准版与全量版中出现了相反判断。

因此，这 60 条“错标”适合作为下一轮重点复核池，不适合作为旧 ID 错标率的最终统计。

## 8.3 当前请求参数

当前客户端实际请求参数为：

- `temperature = 0`；
- `stream = false`；
- `max_tokens = 512`；
- 未设置 `seed`；
- 当前运行命令未显式设置 `--enable-thinking` 或 `--disable-thinking`，因此不发送 `chat_template_kwargs.enable_thinking`；此前报告中 `requests_with_reasoning = 0`，实际没有 reasoning 输出。

所以温度确实是 0，但这不保证服务逐字确定。没有固定 seed，加上动态 batching、并行浮点计算、模型路由及服务状态，完全相同 prompt 仍可能出现不同输出。

## 8.4 题目、释义、历史数据和服务的当前责任判断

| 可能原因 | 当前证据 | 判断 |
|---|---|---|
| 题目缺失/父题问题 | C 类全部为独立题，缺父题为 0，仅 3 条 context_insufficient | 不是主要原因 |
| 题目本身多知识点 | 遗传、膜功能、ATP、内环境等高频 C 类均容易合理多标 | 是扰动放大因素 |
| 释义错误 | 部分 Label 边界冲突，但宽 Label 按项目规则允许合理共标 | 不是统一的“释义错”，更多是边界重叠 |
| 旧 ID 噪声 | C 类中只有 16 条来自边界稳定组；已看到有效补召回与明确历史错标并存 | 重要原因 |
| DS 候选敏感性 | 平均只加 0.508 个候选，却产生大量双向赋值翻转 | 重要原因 |
| DS 服务/重复运行波动 | 温度 0 但无 seed；A 类尚未从 B 类拆出 | 很可能存在，但小包无法量化 |

当前最合理的解释不是单一原因，而是：

```text
历史旧 ID 带入宽边界/相邻知识候选
        ×
题目本身允许多知识点解释
        ×
DS 对最小 Label 集合的选择不稳定
        ×
服务在无 seed 下存在重复运行波动
```

## 9. 原因树

```text
两组 Label 集合不同
├── 候选集合相同
│   └── DS/服务重复运行波动
└── 候选集合扩大
    ├── 新增旧 Label 被选中
    │   ├── 有效补召回
    │   ├── 合理共标
    │   └── 历史错标恢复
    └── 新增旧 Label未被选中
        ├── code/顺序变化
        ├── 候选语义竞争
        ├── 最小子集选择变化
        └── 与模型自身波动叠加
```

## 10. 当前建议

在完成上述精确分组前，不应根据 19.62% 差异率直接判定哪组更好。

建议最终比较采用三套指标：

1. **稳定性指标**：在 `same_candidate_set` 中测量同 prompt 重复运行一致率；
2. **召回收益指标**：只统计 `added_legacy_selected` 中经 Luna 判为 DIRECT_MATCH 或 REASONABLE_CO_LABEL 的部分；
3. **扰动代价指标**：统计候选扩大后，原 Top25 合理 Label 被删除或新增错误 Label 的比例。

如果目标仍是“错标代价高于漏标”，旧 ID 更适合做空结果或扩召请求时的救援候选，而不是无条件追加到所有题目。
