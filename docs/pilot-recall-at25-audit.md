# 300 题候选集人工 Recall@25 审计

审计日期：2026-09-15

## 1. 要回答的问题

本审计只回答一个问题：

> 对每道题，混合召回给出的 25 个候选 Label 中，是否至少包含一个该题真正直接考查的 Label？

这里不评价 DS 是否最终选对，也不要求候选集覆盖题目的全部 Label。只要 Top-25 中至少存在一个明确真 Label，就记为 `hit`。

## 2. 数据与口径

- 题目：300 条审计样本
- representative：200 条
- stress：100 条
- 候选版本：`hybrid-v1-s18-d7-k25`
- Label 总数：458
- 路径分隔符：`@`
- 审计依据：当前小题的 `parent_stem + stem + options + answer_text + analysis`，以及候选 Label 的老师原释义、核心概念和边界说明

判定类别：

- `hit`：至少一个候选明确覆盖当前题目的实际知识需求。
- `miss`：25 个候选都不能直接覆盖当前题目的实际知识需求。
- `invalid_input`：题目本身没有实际设问，或不是生物题，无法定义真 Label。

## 3. 结果

| 项目 | 数量 |
|---|---:|
| 输入题目 | 300 |

## 7. Top-20 与 Top-25 对“至少命中一个”的影响

这 293 条 hit 中，绝大部分在前 20 已经至少有一个真 Label。第 21～25 名候选的主要价值是补充第二、第三个知识点，而不是显著提高“至少命中一个”的题目数。

因此：

- 如果第一阶段目标仅是保证每题至少有一个可用候选，Top-20 已经接近 Top-25。
- 如果最终目标是覆盖多标签题的全部知识点，Top-25 仍有价值，不能仅根据本项指标缩回 Top-20。
- 是否选择 20 或 25，最终还需评价“全部真标签的覆盖率”，而不是只看当前的 `Any-Hit Recall`。

## 8. 对整个方案的判断

混合召回方案通过了“至少一个真 Label”这一基础验证：保守 Recall@25 为 98.32%，说明不需要让 DS 对每题遍历 458 个 Label。

但该结果不能证明候选集合已经完整。前一轮精判审计已经发现多道题只召回或只选择了部分知识点。因此生产前还需要第二个更严格指标：

> `All-Label Coverage@25`：每道题所有应打 Label 是否都进入候选集。

建议后续路线：

1. 保留当前 sparse+dense 混合召回。
2. 修复 #187、#280 两类明确召回规则。
3. 处理 #31、#74、#220 三个 taxonomy gap。
4. 清洗 #101、#202 两类异常输入。
5. 在相同 300 题上继续标注“应有完整 Label 集”，测量 `All-Label Coverage@25`，再决定是否全量运行。
